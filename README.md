# CardKit

Small tools for website editing and template work.

CardKit is a static site of focused browser utilities. No backend, no account, no upload.
Every tool processes content locally in the browser.

Brand: **CardKit** · Subtitle: *Small tools for website editing and template work.*
Support email: **support@xdstudiolab.com** (used on every page, do not reintroduce `info@`)
Production domain: `https://cardcss.top`
Source: `https://github.com/welegent2010/cardkit`
Hosting: Cloudflare Pages, project `cardkit` (`cardkit.pages.dev`)

## Deploy

Upload everything except `tests/` and `output/` to any static host over HTTPS.

The domain is written into canonical tags, the sitemap and `robots.txt`. If you deploy
under a subfolder, change those three places.

**Links are relative** (`tools/...`, `assets/css/site.css`, `../assets/...`), so the site
works from the domain root *and* from a subfolder, and the shared CSS loads even when you
double-click `index.html` from disk. What does not work on `file://` is clicking a
folder link such as `tools/` - a browser will show a directory listing instead of the page.
For a proper local walk-through run a server from this folder:

```sh
python3 -m http.server 8000
# then open http://localhost:8000/
```

Ad slots are written in the HTML but commented out, so the pages do not show an empty box
while AdSense is not live yet. Uncomment the `<aside class="ad">` block to enable a slot.

## Tests

One entry point:

```sh
./tests/run-all.sh
```

`tests/smoke.js` drives both original tools end to end in Playwright: render, edit, export,
plus the invariants that break silently (marker leakage, canvas taint, save inside a
sandboxed frame). It does not cover the content pages.

`tests/hero-shot.js` regenerates `assets/img/hero-editor.jpg` by screenshotting the real
CSS Code Editor at 2x with a demo block pasted in. It needs a network connection, because the
demo card uses a stock photo. Dev-only: it is not part of `run-all.sh`.

## Design system

Dark, restrained, utility-tool character. Do not add decorative motion to tool interfaces.

| Token | Value | Use |
|---|---|---|
| `--bg` | `#121110` | page background |
| `--panel` | `#181614` | cards, panels |
| `--line` | `#2C2926` | borders, dividers |
| `--gold` | `#F5BD63` | accent, links, active state |
| `--muted` | `#9A9186` | body copy |
| `--text` | `#F3EEE6` | headings |

UI font Verdana, headings Georgia. Content width 1160px. Grid breakpoints at 1000 / 820 / 560.

**Pictures.** This is a text-heavy site by nature, so two things stop it reading as a wall of
type and neither should be stripped back out:

- the home hero is two columns, copy left and `assets/img/hero-editor.jpg` right (a real shot
  of the editor, linked to the tool, with a one-line caption). Below 820px it stacks.
- every tool title carries an inline 20x20 SVG in front of it, drawn in `--gold` with
  `stroke-width:1.5` and `currentColor`, so the icons scale with the text and need no files.
  On the two listing pages the icons sit inside `.card h3 .ico`.

## Rules that should not be broken

- **Privacy line** on every tool page, do not shorten: all processing happens locally in the
  browser, files are not uploaded, refresh loses the work.
- **Ads never sit beside a control.** No ad next to COPY, EXPORT, RENDER, UPLOAD, CLEAR,
  sliders or form fields. Ads go between substantial sections or low on the page.
- **CSS Code Editor output is `.html`, never `.txt`.** Export writes a `text/html` blob with a
  `.html` filename so tag structure and indentation survive the trip. Its action bar (COPY HTML /
  EXPORT .HTML / OUTPUT) is `position:sticky` on purpose: the page is over two screens tall, so
  without pinning it you have to scroll down after every edit to find the buttons. Do not un-pin it.
- **CSS Code Editor is positioned for Squarespace custom code blocks** (and HTML templates,
  static pages). Keep the "independent tool, not affiliated with Squarespace" line in its intro.
- **Tools preserve structure.** The CSS Code Editor and HTML Cleaner must never add,
  remove or reorder tags, and must never rewrite classes, IDs, data attributes, inline JS,
  accessibility attributes or URLs. The test suite asserts element count is unchanged.
- **Independence disclaimer** stays in every footer: CardKit is not affiliated with Etsy,
  Squarespace or any other platform mentioned.
- **Support email** is `support@xdstudiolab.com` everywhere.
- **The preview box never gets its own scrollbar.** `.framewrap` has no `max-height` and the
  page does the scrolling; a device wider than the column is scaled with `transform:scale()`
  and the label says so (`1200 px · shown at 84%`). Adding `max-height` back re-creates the
  small box with an inner scrollbar that made long sections painful to read.
- **Card titles line up.** A card that carries a badge gets a matching invisible
  `<span class="badge ghost">` on its neighbours, so titles in a row start on the same line.
  Do not delete those or reach for padding instead.

## Deploy

Built output is the repository root minus the development-only paths. Tests, fixtures and
runtime exports never go up:

```bash
rsync -a --exclude '.git' --exclude '.gitignore' --exclude '.DS_Store' \
      --exclude 'tests' --exclude 'README.md' --exclude 'output' \
      ./ /tmp/cfdeploy/

CI=1 wrangler pages deploy /tmp/cfdeploy \
  --project-name cardkit --branch main --commit-dirty=true
```

24 files, about 572 KB. Cloudflare Pages serves the root `404.html` automatically, and the
directory-style URLs need no rewrite rules.

### Domain

`cardcss.top` and `www.cardcss.top` are both attached to the Pages project. They stay
`pending` until the domain itself is on Cloudflare:

1. dash.cloudflare.com, Add a site, `cardcss.top`, Free plan.
2. Cloudflare hands back two nameservers.
3. At the registrar (this domain is on Spaceship), replace the nameservers with those two.
4. DNS propagation, then the Pages custom domain flips to active on its own.

The OAuth token behind `wrangler login` cannot create zones, so step 1 has to be done by
hand in the dashboard. If Cloudflare's jump-start copies the registrar's parking A records
over (`34.x` / `54.x`), delete those A records before adding the root CNAME, otherwise the
CNAME is rejected for already existing on that host.

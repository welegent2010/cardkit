How to Make a Squarespace Site Look More Professional With 5 Small CSS Changes

Nobody looks at a site and thinks "the border-radius is wrong". They think it looks cheap, or crowded, or unfinished. Those impressions come from a handful of numbers - and five of them do most of the work.

Why five values carry so much weight

A redesign changes everything and fixes nothing if these five are still wrong. Conversely, a plain template with these five handled reads as deliberate. The reason is simple: they are the values a visitor's eye actually registers - the shape of things, the rhythm of the space, the width of the text, the relationship between sizes, and whether anything looks like it is floating.

None of the five requires a new theme, a new font licence or a developer. Each one is a value you can see, which makes them the ideal first edits for someone who does not want to learn CSS.

Identical markup and copy. The difference is radius, spacing, type scale and shadow.

1. Reduce excessive corner radius

Themes and templates default to friendly, generous rounding - often 20px or more on cards, and sometimes full pill radius on buttons. A lot of rounding reads as playful; a small amount reads as precise. Neither is more correct, but "professional for a consultancy, a clinic or a studio" is almost always the smaller number.

  • 0-4px - crisp, editorial, slightly formal
  • 6-12px - the safe middle; soft without being cute
  • 16-24px - friendly, app-like, best for consumer brands
  • 999px - pill. Use it deliberately or not at all

The important part is consistency. A card at 6px with a button at 999px and an image at 20px looks accidental. Pick one radius for large shapes and one for small ones, and apply them everywhere. 

.card, .image-block, .summary-item { border-radius: 8px; }
.button, .sqs-block-button-element { border-radius: 4px; }

2. Establish consistent spacing

Amateur layouts are not usually too tight or too loose overall - they are inconsistent. One section has 40px of breathing room, the next has 12px, and the headings are randomly close to the paragraphs below them. The fix is not artistry, it is a small set of numbers used everywhere.

A workable scale for a small site: 8 / 16 / 24 / 40 / 64. Use 8 or 16 inside components, 24 between related blocks, 40 or 64 between sections. Then stop improvising. 

.section        { padding: 64px 0; }
.summary-item   { padding: 24px; }
h2 + p          { margin-top: 16px; }
.grid           { gap: 24px; }

Which property does what is its own topic - CSS Padding vs. Margin vs. Gap covers the difference, including why setting the padding is usually what you meant.

3. Control content width

Text that runs the full width of a wide monitor is the single fastest way to make a site look unconsidered, and it is also genuinely harder to read. Long lines force the eye to travel back further at the start of each new line, and readers lose their place.

The comfortable range for body text is roughly 60 to 75 characters per line, which in CSS terms is about max-width: 68ch - or a fixed 640-720px if you prefer pixels. 

.sqs-block-html p,
.sqs-block-markdown p { max-width: 68ch; }

Images, galleries and full-bleed sections can stay wide. It is the paragraphs that need reining in, and this one rule changes how finished a page looks more than almost anything else on this list.

4. Improve typographic rhythm

Two numbers do the work here: the size relationship between headings and body text, and line-height.

Scale. If your body text is 17px and your H2 is 34px, the page feels like a poster. If the H2 is 21px, it feels like a document. For most small business sites the sweet spot is a heading roughly 1.4 to 1.8 times the body size - enough to establish hierarchy without shouting.

Line-height. Default leading is usually too tight for reading on screen. Body text wants about 1.6; headings want tighter, around 1.15 to 1.25, because large text with loose leading falls apart. 

p            { font-size: 17px; line-height: 1.6; }
h2           { font-size: 26px; line-height: 1.2; letter-spacing: -0.01em; }
h3           { font-size: 20px; line-height: 1.3; }

One more, if your headings are large and uppercase: a small negative letter-spacing stops big text looking spaced out, and a small positive one stops small uppercase labels looking cramped. Tiny values - 0.01em to 0.08em - and always by eye.

5. Use shadows more carefully

Shadows are where "trying hard" becomes visible. The heavy drop shadow that shipped with your theme, or the one an assistant generated when you asked for "a subtle shadow", is almost always too dark and too large.

A convincing shadow has three qualities: it is low in opacity, it is offset downward only slightly, and its blur is proportional to the element. Big cards get more blur than small buttons. 

/* heavy - reads as dated */
box-shadow: 0 12px 40px rgba(0, 0, 0, .45);

/* restrained - reads as considered */
box-shadow: 0 2px 8px rgba(0, 0, 0, .08);

Two things to check that people miss. First, test the shadow against your real background - a shadow tuned for white becomes a black smear on a dark section. Second, shadows on a dark theme often need to be replaced with a subtle border instead, because dark-on-dark shadows do almost nothing except muddy the edges.

The order to do them in

All five at once is how you end up unable to tell which change helped. Work in this order, because each one changes what the next one should be:

  1. Content width - it changes how much text sits on each line, which affects everything else.
  2. Typographic rhythm - size and leading set the scale the spacing will use.
  3. Spacing - now that text is sized, the gaps can be set against it.
  4. Corner radius - last of the structural values, and easier to judge once the layout is settled.
  5. Shadows - the finishing layer, and the one most likely to be overdone.

Check each one on a phone before moving on. Half of these values are too large on small screens, and the most common professional-looking-site mistake is a desktop that looks tuned and a mobile view that was never opened.

What this will not fix

Worth being straight about, because cosmetic CSS has limits:

  • Weak hierarchy. If the page has no clear order of importance, no amount of spacing will create one. That is a content and structure decision.
  • Bad images. Inconsistent crops, mismatched ratios and low resolution undo every one of the five changes. See Image Size vs. Aspect Ratio and Resizing Product Photos Without Losing Quality.
  • Too many typefaces. Three families on one page is a design problem, and CSS can only reduce it to two.
  • Contrast and accessibility. Light grey text on white looks refined and fails readability. If you change colours, check contrast rather than taste.

Real scenarios

The therapist's practice site. Her theme shipped with 22px card radius and pill buttons, which read cheerful but not clinical. Dropping cards to 6px and buttons to 4px, and widening the line-height on her long paragraphs, took about fifteen minutes and made the site match how she wanted to be perceived.

The photographer with the wall of text. His about page ran edge to edge on a 27-inch monitor. One max-width: 68ch rule fixed the reading experience, and the same rule on his blog posts made the whole site feel composed.

The maker whose shadow was invisible. She added a subtle shadow to her cards on a near-black background and could not see any effect, then doubled it and got a grey haze. The right answer was a 1px border instead, which is what dark themes usually want.

Questions people ask

Do I need to change my theme for this?

No. These are value changes layered on top of whatever theme you have. If your theme is structurally wrong for your content - wrong column behaviour, wrong navigation pattern - that is a different and larger job.

How do I know which numbers suit my brand?

You do not, until you look. That is the whole argument for adjusting visible controls rather than writing CSS: you are making a judgement about your own site, and judgement requires seeing the result.

Will these changes break my mobile layout?

They can. Large padding and fixed widths are the usual culprits. Check the mobile view after each change, and prefer relative units and max-width over fixed pixel widths.

Is it worth hiring someone instead?

For these five, usually not - they are exactly the kind of small, visual, repeatable edit that does not justify a brief and an invoice. The line is drawn elsewhere, and Before You Hire a Designer covers where.

The short version

Five values - radius, spacing, content width, type scale and shadow - decide whether a small site reads as considered. Set them consistently, in that order, and check each one on a phone.

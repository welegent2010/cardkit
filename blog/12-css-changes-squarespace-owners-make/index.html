The 12 CSS Changes Squarespace Site Owners Make Most Often

Not a CSS reference - a list of the dozen requests that come up again and again, each with the complaint, the property that controls it, and what the change actually looks like.

How to read each entry

Every item below follows the same three-part shape, because the order matters more than the code:

  • What people ask - the request in the words it usually arrives in
  • What controls it - the property, and the range that makes sense
  • What happens visually - what you see at each end of that range

The selectors are written generically. On a real Squarespace site you will need the actual class or collection ID for your theme, which you can find with your browser's inspector (right-click the element, choose Inspect). That step - confirming where a rule applies before you paste it - is covered in A Safer Workflow for Editing Squarespace CSS.

1. Button corner radius

"How do I make this button less boxy?"

Controlled by border-radius.

0px sharp 8px neutral 20px friendly 999px pill

Pick one value and use it on every button; inconsistent radii read as accidental.

2. Button padding

"The button feels small and mean."

Controlled by padding - vertical first, horizontal second. Bigger horizontal padding is what makes a button feel confident: 10px 18px is tight, 14px 32px is generous.

Small Comfortable

Vertical padding sets the height; horizontal padding sets how substantial it feels.

3. Section spacing

"There's too much empty space between sections" - or the opposite.

Controlled by padding (or margin) on the section. This is the single biggest lever on how calm a page feels. A common starting point for desktop is 80px 0 and around 48px 0 on mobile - but the right number depends on your type size, so judge it visually.

4. Card corner radius

"The cards look harsh."

Controlled by border-radius on the card. Cards usually want more radius than buttons but less than a pill: 12px to 20px is the common band. Match it to the images inside - a 16px card holding a 0px image looks unfinished.

5. Image corner radius

"My photos look like they were pasted on."

Controlled by border-radius on the image, usually paired with overflow: hidden on the container. Square images inside rounded cards need both, or the corners poke out.

6. Heading size

"The headings are enormous."

Controlled by font-size. The mistake is setting a fixed pixel size that works on desktop and overwhelms a phone. Either set a smaller value inside a mobile media query, or use a relative size. Whatever you choose, check the heading at 390px before you finish - long headings that wrap to four lines are the most common mobile layout problem.

7. Paragraph line height

"My text reads like a block."

Controlled by line-height. Body copy wants roughly 1.5 to 1.7; headings want 1.1 to 1.25. This is the cheapest improvement available on most sites - one number, and long paragraphs suddenly read comfortably.

LINE-HEIGHT 1.2dense LINE-HEIGHT 1.65readable

We print in small batches and ship on Fridays. Orders placed before Wednesday go out the same week.

We print in small batches and ship on Fridays. Orders placed before Wednesday go out the same week.

Same font size. One number apart.

8. Content width

"The text runs right across the screen."

Controlled by max-width on the text container - not by width, which forces a fixed size and causes horizontal scrolling on phones. Around 65 to 75 characters per line is the comfortable range; on most themes that means a max-width somewhere between 640px and 760px for body text.

9. Card shadow

"How do I make the cards lift off the page?"

Controlled by box-shadow: offset, blur and alpha. Subtle wins - small offsets, generous blur, low alpha. Heavy shadows are the fastest way to make a modern site look dated.

HEAVY0 10px 26px rgba(0,0,0,.55) SUBTLE0 6px 22px rgba(0,0,0,.14)

Print studio

Open Thursdays and Fridays.

Both lift the card. Only one looks current.

10. Grid gap

"My three feature cards are jammed together."

Controlled by gap on the grid container - the property peopleforget exists and try to fix with margins on each card, which then needs a different value on the last card. gap handles it in one line.

11. Mobile spacing

"The desktop looks fine but the phone is cramped."

Controlled by the same padding properties, set inside a media query for small screens. Desktop spacing scales down badly: 80px of breathing room becomes a quarter of a phone screen. Reduce section padding and heading size at mobile widths, then check in a private window.

12. Link styling

"The links look like every other site."

Controlled by color, text-decoration and text-underline-offset. A custom colour plus a slightly offset underline is a small change that reads as considered. One caution: never remove the underline from links inside body text without providing another clear signal - colour alone is not enough for every visitor.

Finding the right selector for your theme

Every entry above needs a selector - the part before the curly brace that decides which elements the rule touches. Generic names like .button are illustrations, not something to paste. Getting the real one takes about thirty seconds:

  1. Right-click the element you want to change and choose Inspect. The browser opens with that element highlighted in the HTML.
  2. Read the classes on the highlighted tag. Squarespace uses long, descriptive names - something like .sqs-block-button-element or .image-block. One of those is your selector.
  3. Check how many elements it matches. In the CSS panel of the inspector, or by searching the page for the class, confirm whether it appears once or forty times. Forty means a site-wide change.
  4. Narrow it if you need to. To confine a rule to one page, prefix it with that page's collection ID - the body tag carries one, something like #collection-abc123. #collection-abc123 .button now matches buttons on that page only.
  5. Test in the inspector before pasting. You can type a rule directly into the browser's style panel and see the effect instantly, without saving anything. It is the fastest preview there is and it costs nothing.

That fifth step is worth internalising: the browser inspector is a free sandbox on your live page that nobody else can see. Changes there vanish on refresh, which makes it the ideal place to try a value before committing to it.

What these twelve have in common

Every one of them is cosmetic, reversible and confined to a value. None of them changes the structure of the page, which is exactly why they are safe to do yourself - provided you look at them while you change them and check the result afterwards.

The things that are not on this list - a new multi-column layout, a rebuilt navigation, a full responsive rework, accessibility remediation - are structural, and structural work is where a professional earns their fee. Doing twelve safe changes yourself and hiring someone for the one structural job is a far better trade than paying for all thirteen.

Reduce dependency, don't eliminate expertise. The goal of learning these twelve is not to stop needing designers. It is to stop paying someone every time you want to change 16px to 20px.
